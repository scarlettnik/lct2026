# Алгоритм Java

## Вход и координаты

`SnapshotLoader` получает загруженные объекты из БД. Геометрия переводится из
WGS84 в EPSG:32637. Длины и расстояния считаются в метрах. Идентификаторы,
координаты, число потребителей и топология не зашиты в оптимизатор.

В исправленном конкурсном файле отсутствуют исходные расходы и upstream-ссылки
всех 29 существующих труб. Согласованное допущение: отсутствующий расход равен 0.
`ExistingTopologyResolver` восстанавливает недостающие ссылки по связанным концам
труб, ориентируя их к источнику. Несвязанные компоненты отклоняются. Пропущенный
диаметр камеры берётся как максимум диаметров примыкающих труб. Явные входные
ссылки и диаметры сохраняются. Для оценки с ненулевой существующей нагрузкой
нужно передать её через `flow_tph`.

## Построение и оптимизация

1. Кандидаты врезки: существующие камеры, проекции потребителей на существующие
   линии и точки вдоль этих линий. Правило камеры в пределах 10 м сохраняется.
2. `SharedNetworkBuilder` строит лес подключений. Потребитель может подключиться
   к существующей сети, камере новой сети или новой камере на уже построенной
   ветви. После каждого подключения пересчитываются расходы, DN и S. Существующая
   сеть в актуальной модели не реконструируется.
3. Несколько воспроизводимых порядков подключения дают разные исходные топологии.
   Видимость препятствий кешируется на время построения вариантов одного режима.
4. `JointPlanRefiner` одновременно выбирает позиции камер и врезок на существующих
   линиях. Кандидаты задаются относительно текущей геометрии. Для каждой пары
   позиций смежных узлов вычисляются допустимость и стоимость ребра.
5. `JointChamberMilp` решает дискретную модель с бинарными переменными выбора
   позиций и пар позиций. Для дерева используется точная динамическая программа
   с несколькими лучшими назначениями. Это чистая Java, без внешнего решателя.
6. Все совместные назначения повторно проверяются полным расчётом DN, стоимости
   и инженерным валидатором. Принимается только строгое уменьшение полного S.
7. Переподключение листьев меняет топологию; совместный поиск повторяется после
   него. Таким образом поиск не ограничивается перемещением одного узла.
8. Финальный дискретный отбор выбирает до трёх содержательно различных валидных
   вариантов. Различие оценивается по врезкам, группировке и коридорам трасс.

Точность дискретного решателя относится к заданному набору кандидатов на дереве.
Глобальный минимум непрерывной задачи трассировки этим не доказывается.

### Вход в подключаемое здание

Полигон здания остаётся непроходимым. Исключение разрешено только для финального
прямого участка к подключаемой точке через ближайшую точку внешнего контура здания.
Границы замкнутых внутренних дворов не используются как внешние входы.
`RouteConstraintEngine` сравнивает длину участка внутри полигона с расстоянием
от точки до внешнего контура: вход через дальнюю стену и косой вход через ближайшую стену
отклоняются. `SparseVisibilityRouter` добавляет точки подхода на продолжении
кратчайшего входа; при нескольких равноудалённых стенах проверяются все варианты.
Первый поворот допускается снаружи фасада. Предшествующий ему прямой участок
может однократно пройти от внешней границы отступа до точки поворота, не заходя
в здание. Дополнительные повороты и повторный заход в отступ не допускаются.
Другие препятствия остаются обязательными, включая другие крылья того же здания.
Это правило действует одинаково в 2D и 3D, а также после оптимизации узлов.

Проверка экспорта отдельно объединяет фрагменты новой сети внутри каждого
полигона здания и сравнивает их длины с кратчайшими входами. Прежние показатели
S, полученные с произвольным входом в своё здание, не являются допустимым эталоном.

## Стоимость по техническому приложению

Каждый новый участок, заканчивающийся в существующей камере, добавляет 5 млн рублей.
Присоединение к существующей трубе создаёт новую камеру, её цена включает подключение.
Реконструкция существующих труб и камер в актуальной расчётной модели отключена.

```text
C = новые трубы + новые камеры + врезки в существующие камеры + штраф неподключения
L = длина новых труб
S = 0.7 * C / 25_000_000 + 0.3 * L / 100
```

## Глубина и экспорт

3D строится отдельным поиском с учётом глубины. Для пересечения коммуникации
выбирается проход сверху, если хватает вертикального просвета и места для рамп,
иначе снизу. Обычная глубина 3 м, минимум 0,7 м, уклон не более 0,10.
Газопровод, кабель и существующая тепловая сеть пересекаются на плато длиной 4 м.

Каждый перелом профиля, включая пересечение рамп соседних препятствий, сохраняется
как граница участков и технический узел. Стоимость заглубления считается по
средним коэффициентам концов линейного участка. Независимая проверка контролирует
просвет, плато, уклон и возврат к глубине 3 м в узлах.

2D экспортируется как `[longitude, latitude]`. 3D — как
`[longitude, latitude, -depth]`: условная поверхность имеет Z=0, подземная сеть —
отрицательный Z. Это относительная высота в модели задачи, а не геодезическая
отметка местности. `depth_start` и `depth_end` сохраняют положительную глубину.
Длины для S считаются по горизонтальной проекции в UTM.

Экспорт содержит новые сети и камеры; реконструкция и отдельный tie_in не формируются. Валидатор выходного файла
проверяет размерность координат, соответствие Z глубине, суммы стоимости и длины
объектов и официальную формулу S.

## Проверка

```bash
mvn test
./scripts/verify_project.sh
```

`DatasetQualityTest` использует исправленный входной датасет через настоящий
`SnapshotLoader` с тестовым репозиторием. Проверяет оба режима, подключение всех
ОКС, три разных варианта, пороги S и экспорт. GeoJSON сохраняется в
`target/optimized-results/`. Численный порог относится к этому датасету;
для произвольных входов число допустимых различных решений может быть меньше трёх.
